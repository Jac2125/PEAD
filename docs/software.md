## 0. 이 문서의 목적

분석 코드를 쓰기 전에 **무엇을 만들고, 무엇을 만들지 않으며, 완성을 어떻게 판정하는가**를 고정한다.

일반 소프트웨어 계획서와 다른 점이 하나 있다. 이 프로젝트에서 "버그"는 프로그램이 죽는 것이 아니라 **틀린 숫자를 조용히 내놓는 것**이다. 잘못된 이벤트 정렬이나 미래 정보 누출은 예외를 던지지 않는다. 그냥 그럴듯한 t값을 준다. 따라서 이 계획의 무게중심은 기능 구현이 아니라 **§6 검증 전략**에 있다.

## 1. 범위

### 1.1 목표

S&P 500 편입이 그 기업의 PEAD를 감소시키는가를 검정한다. 처치는 편입에 수반되는 애널리스트 커버리지·유동성·기관 보유의 증가이며, 가설은 정보 과소반응이 처치 후 약해진다는 것이다.

**단순 전후 비교는 쓰지 않는다.** 편입 전 기간은 정의상 편입 후보다 달력시간이 이르고, PEAD는 전 시장에서 장기 감소 추세에 있다. 따라서 관측되는 전후 차이는

$$Y_{\text{후}} - Y_{\text{전}} = \tau + (\text{시간 추세})$$

이며 미지수가 둘이다. 편입되지 않은 매칭 대조군으로 둘째 항을 따로 추정해 제거한다 (§5.3).

### 1.2 비목표 (명시적으로 하지 않는 것)

- 백테스트, 수익률 시뮬레이션, 거래비용 모형, 포트폴리오 구성
- 실시간 데이터 파이프라인, 스케줄러, 서빙 인프라
- 웹 UI, 대시보드
- PEAD의 존재 자체에 대한 재검증 (S&P 500 대형주 null 결과는 기확립으로 취급)

비목표를 적는 이유는 겸손이 아니라 방어다. "열 갈래 길"이 보이는 성향에 대한 구조적 대응이며, 여기 없는 것을 하고 싶어지면 이 문서를 고치는 커밋이 먼저 찍혀야 한다.

## 2. 아키텍처 원칙

### P1. 단방향 데이터 흐름

```
raw  →  interim  →  results
(불변)   (파생)      (파생)
```

`raw`는 한 번 쓰면 수정하지 않는다. 하위 층은 언제든 삭제 후 재생성 가능해야 하고, 실제로 그렇게 되는지 주기적으로 확인한다.

### P2. 자유도의 단일 출처

윈도우 길이, SUE 임계값, 이상치 컷, 최소 관측일 수 등 연구자가 임의로 정할 수 있는 모든 값은 `config.yaml`에만 존재한다. 소스 코드에 숫자 리터럴이 있으면 그것은 버그로 간주한다.

이는 편의 기능이 아니라 **감사 추적 장치**다. 자유도를 만진 이력이 전부 git diff에 남는다. p-hacking에 대한 방어는 의지가 아니라 기록이다.

### P3. 순수 계산과 부수효과의 분리

네트워크 I/O를 하는 코드와 숫자를 계산하는 코드를 같은 함수에 두지 않는다. CAR 계산, 윈도우 정렬, SUE 산출은 전부 `DataFrame → DataFrame` 순수함수여야 하며, 그래야 §6의 합성 데이터 검증이 가능하다.

### P4. 단계 간 디스크 경계

각 단계는 산출물을 디스크에 떨구고 끝난다. 추론 방식을 바꿀 때 재수집이 발생하지 않게 하기 위함이며, 미뤄둔 세 가지 검증(층화표본·경계분석·클러스터 표준오차)을 나중에 싸게 붙이기 위한 구조이기도 하다.

### 3.1 데이터 계약

각 층의 스키마를 여기서 고정한다. 스키마 변경은 이 문서 수정을 동반한다.

**`interim/events.parquet`**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `event_id` | str | `{cik}_{announce_date}` |
| `cik` | str | **주 식별자.** 티커 변경에 불변 (Q2) |
| `ticker` | str | 이벤트 시점 티커. 표시용 |
| `announce_date` | date | 실적 발표일 |
| `announce_timing` | enum | `BMO` / `AMC` / `UNKNOWN` |
| `day0` | date | 초과수익 누적 시작 거래일 |
| `eps_actual` | float | |
| `eps_expected` | float | 애널리스트 컨센서스 (주) |
| `eps_expected_rw` | float | random-walk 기대치 (민감도) |
| `sue` | float | 원값 |
| `sue_rank` | float | 표본 내 십분위 순위 0~1. **주 스펙** |
| `group` | enum | `TREATED` / `CONTROL` |
| `period` | enum | `PRE` / `POST` / `EXCLUDED` |
| `match_id` | str | 매칭쌍 식별자. 대조군은 짝지어진 처치기업을 가리킴 |
| `index_effective_date` | date | 편입·편출 발효일. 대조군은 짝의 날짜를 상속 |
| `event_type` | enum | `ADDITION` / `DELETION` |
| `months_to_event` | int | 발효일 기준 상대 시점 (음수=이전) |

세 가지가 설계상 중요하다.

`group`과 `period`가 분리되어 있어야 DiD가 성립한다. τ는 이 두 지시변수의 **상호작용 계수**로 추정된다.

`match_id`는 대조군 관측치가 어느 처치기업의 짝인지를 기록한다. 표준오차 클러스터링 단위이기도 하다.

`period`의 `EXCLUDED`는 편입일 근처 이벤트를 **데이터에 명시적으로 기록**한다. 코드가 조용히 건너뛰지 않게 하기 위함이다. 대조군은 짝지어진 처치기업의 발효일을 상속받아 같은 배제 구간을 적용한다 — 그래야 두 집단이 동일한 달력 구간을 본다.

**`results/car.parquet`**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `event_id` | str | |
| `spec` | enum | `market_model` / `market_adjusted` / `compromise` |
| `window` | str | 예: `(1,30)` |
| `car` | float | 단일 terminal 값 |
| `n_trading_days` | int | 실제 사용 거래일 수 |
| `est_alpha`, `est_beta` | float | 진단용 |

CAR이 **event당 한 행**이라는 것이 v1 설계 오류에 대한 스키마 수준의 방어다. 경로를 저장하지 않으면 경로를 t-test에 넣는 실수를 할 수 없다.

**`results/tau.parquet`**

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `event_type` | enum | `ADDITION` / `DELETION` |
| `car_spec` | enum | 벤치마크 3종 |
| `sue_spec` | enum | `rank`(주) / `raw` / `decile_spread` |
| `tau_hat` | float | 이중차분 추정치 |
| `se` | float | 클러스터 표준오차 |

이 표는 spec 조합마다 한 행씩 채워진다. 조합 수가 결과 개수이므로 다중검정 문제가 발생한다 — §8 G3에서 다룬다.

## 4. 파이프라인 실행 순서

| 단계 | 스크립트 | 입력 | 출력 | 비고 |
|---|---|---|---|---|
| 01 | `pipelines/run_fetch.py` | config | `raw/` | 유일한 네트워크 단계 |
| 02 | `pipelines/run_match.py` | `raw/` | `interim/matches.parquet` | 대조군 매칭. **결과변수 미사용** |
| 03 | `pipelines/run_build_events.py` | `raw/`, `interim/matches` | `interim/events.parquet` | 자격 필터·배제 구간 태깅 |
| 04 | `pipelines/run_estimate.py` | `interim/` | `results/car.parquet` | CAR 3개 spec 동시 산출 |
| 05 | `pipelines/run_infer.py` | `results/car.parquet` | `results/tau.parquet` | β 추정 + DiD. 여기만 갈아끼우면 재추론 |
| 06 | `pipelines/run_report.py` | `results/` | `reports/` | |

**단계 02가 04보다 앞선다는 것이 중요하다.** 매칭은 CAR을 보기 전에 끝나야 한다. 결과를 보고 매칭을 조정하면 대조군이 시간 추세의 중립적 추정치가 아니게 된다.

숫자 접두어 대신 `run_` 명명을 쓴다. `01_fetch.py`는 파이썬 식별자가 아니라 임포트할 수 없고, 나중에 단계를 묶어 호출하고 싶어질 때 걸린다. 실행 순서는 파일명이 아니라 이 표가 정본이다.

단계 04가 세 벤치마크 spec을 **항상 함께** 산출하고, 단계 05가 세 SUE spec을 항상 함께 산출한다. 결과를 보고 spec을 고르는 경로를 구조적으로 차단한다.

## 5. 요구사항

### 5.1 기능 요구사항

- FR1. 편입·편출 이력을 발효일과 함께 수집한다.
- FR2. 처치·대조 양 집단의 발효일 전후 N분기 실적 발표일, EPS 실적치, 애널리스트 컨센서스를 수집한다.
- FR3. 이벤트별 terminal CAR을 세 가지 벤치마크 spec으로 산출한다.
- FR4. §5.4의 기준으로 대조군을 매칭하고 매칭 품질 진단표를 낸다.
- FR5. §5.3의 τ를 상호작용 회귀로 추정하고, 기업 수준 클러스터 표준오차를 낸다.
- FR6. 처치 이전 구간에서 평행추세를 사전검정한다.
- FR7. 편입과 편출에 동일 절차를 적용해 τ의 부호를 대조한다.

### 5.2 정확성 요구사항 (기능보다 우선)

- CR1. **미래 정보 불사용.** 추정윈도우는 이벤트윈도우보다 전부 앞선다. 갭을 둔다.
- CR2. **관측 단위 = 기업.** 한 기업의 여러 분기 CAR은 상관되어 있다. 유효 표본은 이벤트 수가 아니다.
- CR3. **날짜 클러스터링.** 같은 날 발표한 기업들의 CAR은 상관되어 있다.
- CR4. **구성종목 시점 정합.** 이벤트 시점의 구성종목을 쓴다. 현재 스냅샷은 survivorship bias를 만든다.
- CR5. **결측의 명시적 처리.** 데이터 없음을 조용히 dropna하지 않는다. 사유별로 태깅한다.
- CR6. **매칭 시점 정합.** 매칭 변수는 발효일 **직전** 값이어야 한다. 현재 시점 값으로 매칭하면 매칭이 아니다 (§5.5).
- CR7. **매칭은 결과변수를 보지 않는다.** 단계 02는 CAR에 접근하지 않는다.

### 5.3 추정 대상 (estimand)

#### PEAD의 크기 = SUE 회귀 기울기

PEAD는 수익률의 **수준**이 아니라 서프라이즈와 이후 drift의 **연관 강도**다. CAR을 단순 평균하면 좋은 서프라이즈의 양수 CAR과 나쁜 서프라이즈의 음수 CAR이 상쇄되어, PEAD가 강해도 평균은 0 근처가 된다.

따라서 PEAD를 다음 기울기로 정의한다.

$$\text{CAR}_i = \alpha + \beta \cdot \text{SUE}_i + \varepsilon_i$$

β > 0이면 PEAD 존재, β = 0이면 부재. 나쁜 서프라이즈 뒤의 음수 CAR은 기울기를 **키우므로** 상쇄 문제가 발생하지 않는다.

**선형성은 가정이지 사실이 아니다.** 실제 관계는 극단 서프라이즈에서 포화되거나 호재·악재 간 비대칭일 수 있다. 더 심각하게는, 편입 전후로 SUE 분포 자체가 이동하면 참 β가 같아도 β̂이 달라진다. 이 때문에 **십분위 순위 회귀를 주 스펙으로 삼는다.** 순위 변환은 단조성만 요구하므로 곡률과 분포 이동에 둔감하고, "SUE 한 단위당" 해석을 잃는 대신 검정력은 대부분 보존한다.

SUE spec 3종을 항상 함께 산출한다.

| spec | 정의 | 지위 |
|---|---|---|
| `rank` | SUE 십분위 순위 0~1 | **주** |
| `raw` | SUE 원값 | 민감도 |
| `decile_spread` | 최상위 − 최하위 십분위 평균 CAR | 민감도. 함수 형태 가정 없음, 검정력 낮음 |

#### τ = β의 이중차분

$$\tau = \left(\beta^{\text{처치}}_{\text{후}} - \beta^{\text{처치}}_{\text{전}}\right) - \left(\beta^{\text{대조}}_{\text{후}} - \beta^{\text{대조}}_{\text{전}}\right)$$

첫 차분이 기업 고유 특성을, 둘째 차분이 시간 추세를 제거한다.

**구현은 네 β를 따로 추정해 빼지 않는다.** 삼중 상호작용 회귀로 τ를 직접 추정한다. 표준오차가 자동으로 나오고, 손으로 빼면 공분산 항을 놓친다.

$$\text{CAR}_i = \gamma_0 + \gamma_1 S_i + \gamma_2 P_i + \gamma_3 G_i + \gamma_4 (S_i P_i) + \gamma_5 (S_i G_i) + \gamma_6 (P_i G_i) + \tau (S_i P_i G_i) + \varepsilon_i$$

S = SUE(순위), P = 사후 지시변수, G = 처치집단 지시변수. τ가 삼중 상호작용 계수다. 기업 수준 클러스터 표준오차를 쓴다 (CR2).

#### 가설

$$H_0: \tau = 0 \quad\text{vs}\quad H_1^{\text{편입}}: \tau < 0, \quad H_1^{\text{편출}}: \tau > 0$$

τ의 **값**이 아니라 **부호**에 대한 주장이다. 대립가설을 점으로 잡으면 참값이 다른 음수일 때도 기각되므로 방향으로만 건다.

#### 반증 조건 (Q7)

사전에 고정한다. 결과를 본 뒤 수정하지 않는다.

- **F1.** 편입 표본에서 주 스펙 τ̂의 단측 p ≥ 0.05이면 주 가설은 지지되지 않는다.
- **F2.** 편입 τ̂와 편출 τ̂의 부호가 같으면, 설계가 커버리지가 아닌 무언가를 잡고 있다는 신호로 간주한다. 편출 표본이 M&A 오염으로 소실될 경우 F2는 판정 불능으로 기록한다 (RK8).
- **F3.** 평행추세 사전검정에서 처치 이전 구간의 집단 간 β 추세가 유의하게 다르면, DiD의 식별 가정이 깨진 것으로 보고 τ̂를 인과적으로 해석하지 않는다.
- **F4.** SUE spec 3종 간 τ̂의 부호가 갈리면 결론을 유보하고 그 사실을 보고한다.
- **F5.** 오염 배제폭 민감도 밴드(주 폭의 0.5배·2배)에서 부호가 뒤집히면 결과를 오염 구간에 의존하는 것으로 기록한다.

**크기 대칭은 요구하지 않는다.** 편출 τ는 편입보다 클 수 있다 — 편입은 커버리지가 이미 상승 중인 기업에 주어지는 반면 편출은 상대적으로 급작스럽다. F2는 부호만 본다.

### 5.4 대조군 매칭 설계

#### 원칙

매칭 변수는 **처치 배정을 결정하는 변수**여야 한다. 배정 주체는 S&P 지수위원회이므로, 공식 편입 기준이 변수 목록의 출발점이다.

공식 기준: 미국 소재, 최소 시가총액, 주요 거래소 상장, 상장 12개월 이상, 4분기 연속 흑자, 유동주식비율 10% 이상. 최종 결정은 위원회 재량.

#### 매칭 변수

| 변수 | 근거 | 출처 |
|---|---|---|
| 시가총액 | 공식 기준. 위원회가 업종 대표기업 선정에 사용 | 가격 × 발행주식수 (시점별) |
| 직전 12개월 수익률 | 위원회는 주가 부진 기업을 편입하지 않음 → 편입 확률 결정 변수 | 가격 |
| 4분기 연속 흑자 | 공식 기준. 자격 필터로 사용 | EDGAR |
| 2자리 SIC | 업종 정합 | EDGAR submissions |

**Tobin's q는 쓰지 않는다.** 공식 기준에 없어 처치 배정 변수로서 근거가 약하고, XBRL 태그 조합이 필요해 구현 비용이 가장 크며, 매칭 변수를 늘리면 검정력이 오히려 떨어진다는 보고가 있다. 표본이 100건 안팎인 이 설계에서 이 손실은 실질적이다. 문헌에서 Tobin's q를 쓴 연구들은 Compustat 접근권이 있었다.

#### 절차

1. **후보 풀**: 표본 기간 중 S&P 500에 한 번도 속하지 않은 기업 중 자격 요건(상장 12개월·4분기 흑자·거래소)을 만족하는 기업.
2. **매칭 시점**: 발효일 **직전 회계연도 말**. 처치 이후 정보는 일절 사용하지 않는다.
3. **매칭 방식**: 2자리 SIC 완전일치 조건 하에서 시가총액·직전 수익률 거리 최소화. 처치기업 1곳당 대조군 1곳.
4. **품질 진단**: 매칭 후 두 집단의 매칭 변수 분포를 비교한 표를 낸다. 유의한 차이가 남으면 그 사실을 보고한다.
5. **대조군의 가상 발효일**: 짝지어진 처치기업의 발효일을 상속한다. 그래야 두 집단이 동일 달력 구간을 본다.

#### 평행추세

DiD의 식별 가정은 "처치가 없었다면 두 집단의 β가 같은 속도로 변했을 것"이다. 사후에는 검증 불가능하지만 **사전 구간에서는 관측된다.** 발효일 이전 여러 분기에 대해 집단별 β 추세를 추정하고 차이를 검정한다 (FR6). 이 검정이 F3의 근거다.

### 5.5 데이터 출처와 시점 정합성

**yfinance는 가격 데이터용으로만 쓴다.** 재무 항목은 최근 4~5개 연도만 제공하고 그것도 현재 시점 기준이라, 2015년 편입 건에 필요한 2014년 말 총자산을 받을 수 없다. `info`의 시가총액도 오늘 값이다.

| 항목 | 출처 | 비고 |
|---|---|---|
| 일별 가격·수익률 | yfinance | 스냅샷 후 불변 보관 (R3) |
| 발행주식수 시계열 | EDGAR | 시점별 시가총액 재구성용 |
| 순이익 (흑자 판정) | EDGAR companyconcept | |
| SIC 코드 | EDGAR submissions | 현재 값. 업종 변경 이력 없음 — 대개 무해 |
| CIK ↔ 티커 매핑 | SEC `company_tickers.json` + `formerNames` | 과거 티커 해석 (Q2) |
| 실적 발표일·EPS·컨센서스 | yfinance | 편입 이전 구간 가용성이 병목 (RK5) |
| 편입·편출 이력 | 위키피디아 + 교차확인 | |

**Q4 미해결 긴장**: 처치가 애널리스트 커버리지인데 측정 도구도 애널리스트 예측이다. 편입 전 커버리지 3명, 후 15명이면 컨센서스의 분산·편향이 처치와 함께 변해 SUE 척도가 전후로 달라진다. random-walk SUE는 정확도가 낮지만 척도가 불변이다. **양쪽을 모두 산출하고 결론이 척도에 의존하는지 본다.**

#### 오염 배제 구간 (Q6)

**결과변수를 보고 정하지 않는다.** CAR을 여러 배제폭으로 계산해 깔끔한 폭을 고르는 것은 p-hacking이다.

대신 **거래량**으로 정한다. 인덱스 자금 흐름은 가격보다 거래량에 선명하게 남는다. 발효일 전후 구간에서 추정윈도우 평균 대비 일별 거래량 비율을 그리고, 기준선 복귀 시점을 오염 종료로 본다. 거래량은 이 연구의 결과변수가 아니므로 이를 보고 정해도 결론을 오염시키지 않는다.

주 배제폭 1개와 민감도 밴드(0.5배·2배)를 **동시에** 사전등록한다. 사후에 폭을 고르는 것과 사전에 범위를 선언하는 것은 다르다.

## 6. 검증 전략 ★

이 프로젝트의 중심이다. 통계 코드는 틀려도 정상 종료되므로, 일반적인 단위 테스트만으로는 부족하다. 세 층으로 방어한다.

### 6.1 불변식 테스트

계산 결과가 만족해야 하는 성질을 코드로 박아둔다.

- `est_window_end < event_window_start` — 모든 이벤트에서 참
- `n_trading_days == config.window_length` — 아니면 해당 이벤트 탈락
- `event_id` 유일성
- BMO/AMC에 따른 `day0` 정의가 일관
- `period` 태깅이 배제 구간과 모순 없음
- 모든 매칭 변수의 관측 시점 < 해당 `index_effective_date` (CR6)
- 대조군 CIK가 표본 기간 중 S&P 500 구성종목 이력에 등장하지 않음
- 각 `match_id`에 `TREATED` 1건과 `CONTROL` 1건이 존재
- `sue_rank`가 [0,1] 범위이고 그룹·기간 내에서 단조

### 6.2 합성 데이터 오라클 ★★

**정답을 아는 데이터를 만들어 파이프라인이 그 정답을 되찾는지 본다.** 실제 데이터에서는 참값을 모르므로, 이것이 파이프라인의 정확성을 확인할 수 있는 유일한 방법이다.

| 테스트 | 생성 | 기대 결과 |
|---|---|---|
| T1 귀무 | drift 없는 기하 브라운 운동 | p값이 균등분포, 기각률 ≈ 유의수준 |
| T2 회수 | 알려진 크기 d의 drift 주입 | 추정 CAAR이 d를 신뢰구간 안에서 회수 |
| T3 alpha anchoring | α≠0, 실제 drift 0 | market model CAAR은 선형 증가, 대칭 윈도우 CAR_diff는 0 |
| T4 클러스터 | 같은 날짜에 상관된 이벤트 | 단순 t는 과대기각, 클러스터 보정 후 정상 |
| T5 누출 | 이벤트 직후에만 신호 주입 | 추정윈도우 계수가 영향받지 않음 |
| **T6 τ 회수** | 알려진 β를 네 셀에 심되 **양 집단에 동일한 시간 추세**를 부여 | 단순 전후 비교는 편향, **DiD는 참 τ를 회수** |
| **T7 비선형 SUE** | 참 관계를 포화형으로 생성하고 전후로 SUE 분포를 이동 | 원값 회귀 β̂은 τ가 0인데도 변화, **순위 회귀는 안정** |

**T3**는 지난 프로젝트에서 직접 유도한 결과 — 대칭 윈도우에서 Tα̂ 항이 대수적으로 소거된다 — 를 회귀 테스트로 고정한 것이다.

**T6이 이번 설계의 핵심 테스트다.** DiD가 시간 추세를 실제로 제거하는지를 정답이 있는 데이터에서 확인한다. 시간 추세만 있고 처치 효과가 0인 경우(τ=0)도 함께 돌려, DiD가 거짓 양성을 내지 않는지 본다.

**T7은 §5.3의 spec 선택 근거를 검증한다.** 순위 변환이 분포 이동에 둔감하다는 주장이 코드 수준에서 참인지 확인하는 것이다. 이것이 통과하지 않으면 주 스펙을 바꿔야 한다.

**T1과 T6은 검정력 계산의 재료이기도 하다.** 실제 표본 크기(**기업 수**, 이벤트 수가 아님)와 실제 CAR 표준편차로 반복하면 검출 가능한 최소 τ가 나온다. DiD는 차분을 두 번 하므로 단순 비교보다 분산이 크다 — 검정력 손실을 반드시 반영한다.

### 6.3 외부 벤치마크 대조

전체 파이프라인을 문헌에 결과가 알려진 설정으로 한 번 돌린다. 부호와 대략적 크기가 문헌과 어긋나면 설계가 아니라 구현을 의심한다.

## 8. 프로세스 통제 (p-hacking 방어)

- G1. `docs/preregistration.md`가 분석 코드보다 **먼저** 커밋된다. 타임스탬프가 증거다.
- G2. 사전등록 이후 config 변경은 별도 커밋으로 사유를 남긴다.
- G3. 단계 04·05는 모든 spec 조합을 항상 함께 낸다. 사후 선택 불가.
- G4. 탐색적 분석은 `notebooks/exploratory/`에 격리하고, 결과 주장에 인용하지 않는다.
- G5. 반증 조건(F1~F5)이 충족되면 문서에 기록한다. 조건을 고치지 않는다.
- G6. **주 스펙을 §5.3에서 미리 지정했다** — CAR은 대칭 윈도우 CAR_diff, SUE는 `rank`. 나머지는 민감도이며 결론은 주 스펙으로 낸다.
- G7. 매칭(단계 02)은 CAR을 산출하기 전에 완료하고 그 결과를 커밋한다 (CR7).
- G8. 선형성 확인용 산점도는 처치·기간 구분 **없이 통합 표본으로만** 그린다. 집단별로 나눠 보고 스펙을 고르는 것은 금지.

**다중검정 주의**: CAR spec 3종 × SUE spec 3종 × 편입·편출 2종 = 18개 결과가 나온다. 이 중 하나가 p < 0.05인 것은 우연으로도 흔하다. G6의 주 스펙 지정이 이에 대한 방어이며, 민감도 스펙은 부호 일관성 확인용이지 별도 검정이 아니다.

G5가 가장 지키기 어렵다. 이 문서에 적어두는 이유가 그것이다.

**M2가 M4보다 앞선다.** 파이프라인이 옳음을 확인한 뒤에 실제 데이터를 본다. 반대 순서로 하면 결과를 본 상태에서 코드를 고치게 되고, 그때부터 수정은 중립적이지 않다.

**M3에 중단 조건이 있다.** 검정력이 부족하면 M4로 넘어가지 않는다. DiD는 단순 비교보다 분산이 크므로 이 관문이 이전보다 엄격해졌다.

**M5가 M7보다 앞선다.** 매칭은 결과를 보기 전에 끝나야 한다 (G7).

## 부록 A. 이 계획서의 한계

이 문서는 재민 님과의 대화 맥락에서 복원한 것이며, 잃어버린 코드의 세부 구현은 반영되어 있지 않다. 특히 §3의 스키마는 제안이지 기록이 아니다. 이전 파이프라인과 다른 부분이 있다면 그것은 재민 님의 기억이 정본이다.

**v1.0에서 새로 들어온 위험**: 이 개정으로 설계는 식별 측면에서 크게 나아졌지만 **구현 부담과 검정력 요구가 동시에 올라갔다.** 대조군 매칭은 표본을 두 배로 만들고 EDGAR 시점 정합을 요구하며, DiD는 차분을 두 번 하므로 분산이 커진다. M3의 중단 조건이 이전보다 실질적인 관문이라는 뜻이다. 검정력이 부족하다는 결과가 나오면, 그것을 설계 실패가 아니라 **연구가 답할 수 있는 질문의 경계를 알아낸 것**으로 기록하고 멈춘다.

**문헌 대비 위치**: S&P 500 편입의 DiD 연구는 이미 존재하며, 편입이 애널리스트 커버리지·미디어 노출을 증가시킨다는 것은 기존 문헌에서 확인되었다. 즉 이 연구는 처치의 존재를 증명할 필요가 없고, **그 커버리지 증가가 PEAD를 줄이는가**만 보면 된다. 기존 연구들은 Compustat·I/B/E/S 접근권을 전제하므로, 무료 데이터로 같은 질문에 접근하는 것 자체가 이 프로젝트의 제약이자 특징이다.
